## 💻 Technical Questions
## 💻 أسئلة تقنية

### Q6: I get "python is not recognized" error. What should I do?
### س6: أحصل على خطأ "python is not recognized". ماذا أفعل؟

**A:** This means Python isn't in your system PATH. Try:
- Windows: Use `py` instead of `python`
- macOS/Linux: Use `python3` instead of `python`
- Or reinstall Python and check "Add to PATH" during installation

**ج:** هذا يعني أن بايثون ليس في مسار النظام. جرّب:
- Windows: استخدم `py` بدلاً من `python`
- macOS/Linux: استخدم `python3` بدلاً من `python`
- أو أعد تثبيت بايثون وتحقق من "Add to PATH" أثناء التثبيت

---

### Q7: What's a virtual environment and why do I need it?
### س7: ما هي البيئة الافتراضية ولماذا أحتاجها؟

**A:** A virtual environment is an isolated Python workspace for your project. It keeps your project dependencies separate from other projects. Think of it as a clean room for each project.

**ج:** البيئة الافتراضية هي مساحة عمل بايثون معزولة لمشروعك. تحافظ على تبعيات مشروعك منفصلة عن المشاريع الأخرى. فكر فيها كغرفة نظيفة لكل مشروع.

---

### Q8: VS Code or PyCharm - which should I use?
### س8: VS Code أم PyCharm - أيهما يجب أن أستخدم؟

**A:** We recommend **VS Code** because:
- It's free and lightweight
- Great for beginners
- Works well with our Dr. Laila AI assistant
- Industry standard for many companies

PyCharm is also excellent but might be overwhelming for beginners.

**ج:** نوصي بـ **VS Code** لأنه:
- مجاني وخفيف
- رائع للمبتدئين
- يعمل جيداً مع مساعدنا الذكي د. ليلى
- معيار صناعي للعديد من الشركات

PyCharm أيضاً ممتاز لكن قد يكون مربكاً للمبتدئين.

---

### Q9: How do I know if my code is good?
### س9: كيف أعرف إذا كان كودي جيداً؟

**A:** Good code should be:
1. **Working** - Does what it's supposed to do
2. **Readable** - Others can understand it
3. **Efficient** - Doesn't waste resources
4. **Following PEP 8** - Python's style guide

Use our cheatsheets and run `flake8` to check your code style!

**ج:** الكود الجيد يجب أن يكون:
1. **يعمل** - يفعل ما يُفترض أن يفعله
2. **مقروء** - الآخرون يمكنهم فهمه
3. **فعّال** - لا يضيع الموارد
4. **يتبع PEP 8** - دليل أسلوب بايثون

استخدم أوراق الغش الخاصة بنا وشغّل `flake8` لفحص أسلوب كودك!

## 🔧 أسئلة Git و GitHub

### Q12: What's the difference between Git and GitHub?
### س12: ما الفرق بين Git و GitHub؟

**A:**
- **Git**: Version control system (tracks changes in your code)
- **GitHub**: Website that hosts Git repositories online

Think of Git as the engine and GitHub as the parking garage.

**ج:**
- **Git**: نظام التحكم بالإصدار (يتتبع التغييرات في كودك)
- **GitHub**: موقع يستضيف مستودعات Git على الإنترنت

فكر في Git كالمحرك و GitHub كموقف السيارات.

## 📖 Study Tips
## 📖 نصائح دراسية

### Q15: How many hours should I study per week?
### س15: كم ساعة يجب أن أدرس أسبوعياً؟

**A:** There's no fixed schedule, but as a guide, plan for:
- 2-3 hours working through each chapter (slides + Dr. Laila)
- 3-4 hours self-study and practice
- **Total: 5-7 hours per chapter, at whatever pace suits you**

Programming is like learning a musical instrument - regular practice is key, more than any specific number of hours!

**ج:** لا يوجد جدول ثابت، لكن كدليل، خطط لـ:
- 2-3 ساعات لدراسة كل فصل (الشرائح + الدكتورة ليلى)
- 3-4 ساعات دراسة ذاتية وممارسة
- **المجموع: 5-7 ساعات لكل فصل، بالسرعة التي تناسبك**

البرمجة مثل تعلم آلة موسيقية - الممارسة المنتظمة هي المفتاح، أكثر من أي عدد ساعات محدد!

### Q16: I'm stuck on a problem. What should I do?
### س16: أنا عالق في مشكلة. ماذا أفعل؟

**A:** Follow this process:
1. **Read the error message** - Python tells you what's wrong
2. **Check your syntax** - Missing colons, parentheses, indentation?
3. **Use Dr. Laila** - Ask for hints, not solutions
4. **Check the examples** - Similar code in `code-examples/`
5. **Take a break** - Sometimes stepping away helps
6. **Ask for help** - Open a GitHub issue, or search Stack Overflow

**ج:** اتبع هذه العملية:
1. **اقرأ رسالة الخطأ** - بايثون يخبرك ما الخطأ
2. **تحقق من الصياغة** - نقطتان ناقصة، أقواس، مسافات بادئة؟
3. **استخدم د. ليلى** - اطلب تلميحات، ليس حلولاً
4. **تحقق من الأمثلة** - كود مشابه في `code-examples/`
5. **خذ استراحة** - أحياناً الابتعاد يساعد
6. **اطلب المساعدة** - افتح GitHub issue، أو ابحث في Stack Overflow
